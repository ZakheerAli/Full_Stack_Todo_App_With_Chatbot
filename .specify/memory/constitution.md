PROJECT CONSTITUTION
====================

Hackathon II -- The Evolution of Todo
------------------------------------

### Phase 2: Full-Stack Todo Web Application

### Phase 3: AI-Powered Todo Chatbot

* * * * *

Version & Authority
-------------------

-   **Version:** 3.0.0 (FINAL)

-   **Status:** ACTIVE - NON‑NEGOTIABLE

-   **Adopted:** 2026-01-12

-   **Last Amended:** 2026-01-12

-   **Scope:** Phase 2 + Phase 3

This Constitution is the **supreme law** of the project. Any conflict between this document and any spec, task, plan, or implementation will always be resolved **in favor of this Constitution**.

* * * * *

1. Purpose & Vision
--------------------

The purpose of this Constitution is to define **how the project must be built**, not just *what* is built.

This project demonstrates:

-   Spec‑Driven Development

-   AI‑Native Architecture

-   Reusable Intelligence

-   Clean, scalable, cloud‑ready engineering

The system evolves from a **full‑stack Todo web app (Phase 2)** into an **AI‑powered conversational assistant (Phase 3)** without rewrites or architectural breaks.

* * * * *

2. Core Non‑Negotiable Principles
----------------------------------

### 2.1 Spec‑Driven Development (SDD)

-   ❌ No feature may exist without a written Markdown spec

-   ❌ No implementation without an approved spec

-   ✅ Workflow is mandatory:
    **Spec → Plan → Tasks → Claude Code/Gemini CLi → Verification**

-   Specs must be versioned and stored under `/specs`

* * * * *

### 2.2 No Manual Coding Law

-   ❌ Humans MUST NOT write production code manually

-   ✅ All production code MUST be generated by **Claude Code/Gemini Cli**

-   Manual edits allowed ONLY for:

    -   Environment variables

    -   Secrets

    -   Deployment configuration

Violation → immediate rollback

* * * * *

### 2.3 Incremental Evolution Law

-   Phase 2 → Phase 3 MUST evolve, never rewrite

-   Breaking changes require a migration plan

-   Phase 2 backend services MUST be reusable by Phase 3 chatbot

* * * * *

### 2.4 Modularity & Reusable Intelligence

-   Business logic MUST live in reusable services or skills

-   UI layers must never contain core logic

-   Skills must be interface‑agnostic (Web, API, Chatbot)

* * * * *

### 2.5 AI‑Native First

-   Agents, sub‑agents, and skills are first‑class architectural units

-   Reusable Intelligence is mandatory (Hackathon bonus alignment)

* * * * *

3. Global Technology Law
-------------------------

### 3.1 Phase 2 -- Locked Technology Stack

| Layer | Technology |
| --- | --- |
| Frontend | Next.js 16+ (App Router, TypeScript) |
| Backend | Python FastAPI |
| ORM | SQLModel |
| Database | Neon Serverless PostgreSQL |
| Authentication | Better Auth (JWT) |
| Spec‑Driven | Claude Code + Spec‑Kit Plus |

❌ Substitutions are forbidden without constitutional amendment

* * * * *

### 3.2 Phase 3 -- AI Technology Boundaries (Constitution Level)

Mandatory:

-   AI orchestration via **OpenAI Agents SDK or equivalent**

-   **MCP (Model Context Protocol)** for tool usage

-   Stateless reasoning + persistent memory layer

Rules:

-   ❌ Chatbot MUST NOT access database directly

-   ✅ All actions go through Phase 2 APIs or Skills

-   All memory must be auditable and explainable

Optional (Bonus):

-   Voice interface

-   Multi‑language support (Urdu mandatory)

* * * * *

4. Global Coding Standards (Strict)
------------------------------------

### 4.1 Universal Rules

-   Code must be readable, modular, testable, documented

-   ❌ God files forbidden

-   ❌ Hidden side effects forbidden

-   ❌ Tight coupling forbidden

* * * * *

### 4.2 Backend Coding Law (FastAPI)

Mandatory:

-   Layered architecture: **API → Service → Model**

-   Dependency Injection required

-   Pydantic v2 schemas only

-   SQLModel ORM only

Forbidden:

-   ❌ Business logic in routes

-   ❌ Raw SQL in API layer

-   ❌ Shared mutable state

* * * * *

### 4.3 Frontend Coding Law (Next.js)

Mandatory:

-   App Router only

-   Server Components by default

-   Client Components only when necessary

-   Strict TypeScript

Forbidden:

-   ❌ `any` type

-   ❌ Hardcoded strings (i18n required)

-   ❌ Business logic inside JSX

* * * * *

5. Authentication & Security Constitution
------------------------------------------

-   Better Auth is the ONLY allowed auth system

-   JWT‑based authentication mandatory

-   Email verification required

Security Laws:

-   User isolation at:

    -   Database level

    -   API level

    -   UI level

-   Rate limiting mandatory

Forbidden:

-   ❌ Custom auth implementations

-   ❌ Cross‑user data access

* * * * *

6. Testing & Quality Gates (Blocking)
--------------------------------------

Mandatory:

-   Minimum **80% test coverage**

-   All tests must pass before merge or deploy

Test Types:

-   Unit

-   Integration

-   E2E

-   Accessibility

Failure → deployment blocked

* * * * *

7. Accessibility Constitution (WCAG 2.1 AA)
--------------------------------------------

Mandatory:

-   Full keyboard navigation

-   Screen reader compatibility

-   Proper ARIA roles

-   Focus management in modals

-   Reduced motion support

* * * * *

8. Performance Law
-------------------

Mandatory Targets:

-   API P95 < 500ms

-   Task list load < 2s (1000 tasks)

-   Lighthouse Performance ≥ 90

Forbidden:

-   ❌ Unbounded queries

-   ❌ Non‑virtualized large lists

* * * * *

9. Phase 2 ↔ Phase 3 Binding Rules
-----------------------------------

-   Phase 2 APIs MUST support chatbot use without modification

-   All chatbot actions must be explainable

-   Destructive actions require confirmation

* * * * *

10. AI Chatbot Behavioral Law (Phase 3)
----------------------------------------

-   Explain intent before execution

-   Ask confirmation for destructive actions

-   Never hallucinate data

-   Operate only within granted tools

* * * * *

11. Documentation Law
----------------------

Mandatory:

-   All modules documented

-   ADRs for major decisions

-   Specs versioned and maintained

* * * * *

12. Violation Handling Protocol
--------------------------------

If any rule is violated:

1.  Stop implementation

2.  Roll back changes

3.  Fix specification

4.  Re‑run Claude Code

* * * * *

13. Amendment Process
----------------------

This Constitution may be changed only by:

-   Written amendment spec

-   Explicit version bump

-   Full architectural review

* * * * *

Final Authority Clause
----------------------

This Constitution overrides:

-   Specs

-   Plans

-   Tasks

-   Implementations

Compliance is **mandatory**.

* * * * *

**END OF FINAL CONSTITUTION**
